## 1. 定位与已确认边界

设备定位为纯粹硬件钱包，是可理解请求、独立核验、物理授权并执行密码学操作的终端，与 Keymaster 软件 Vault 使用相同身份和业务语义。主机联网、构造请求、搬运证据和广播；设备保管 Key，解释实际操作；用户通过屏幕与三实体按钮决定。

已确认：ESP32/M5Stack、三实体按钮、USB 浏览器互联、设备独立解锁、操作白名单、一次/会话允许与否决、设备可取消持续决定、基础操作摘要/完整对象可滚动、多语言选择性编译。设备第一版只服务一个 Keymaster 身份 Key，不提供 Key 列表/切换。FIDO、设备保护密钥或实验子系统的隔离秘密不算第二个业务钱包身份，但不纳入首版钱包功能。

尚未确定具体 M5Stack SKU/修订版。三按钮 BASIC/FIRE 与 ESP32-S3 不能混为同一平台；先确认芯片、屏幕、Flash/PSRAM、USB 桥、电池和调试接口。以 BASIC v2.7 为候选时按 USB 转串口评估 Web Serial，不假定原生 HID/CTAP2。无线正常钱包固件关闭；有电池时 USB 断开仍须独立锁定。

ESP32 是通用 MCU，当前定位为实验/开发/协议验证。PIN、Secure Boot 与 Flash Encryption 不等同于专用安全芯片的物理抗攻击能力。

## 2. 单 Key 与密钥保护

设备只保存一个业务私钥及公钥。支持迁入现有 Key，保持身份、Channel 和本地秘密兼容；也规划设备生成/恢复 Key 后绑定空 Keymaster 钱包。已有 Key 的设备拒绝不同 Key 覆盖，只有明确设备擦除后才能更换。设备恢复同一 Key 不要求删除浏览器数据，主机必须验证公钥与持有权。

建议默认不保存旧软件 KeyHold 或旧密码解密旁路；这是用户倾向、待最终确认的决策。私钥在设备内用版本化认证加密封装，口令派生与设备保护材料参与解锁。随机盐、随机数、参数、密文和格式升级分别管理；业务 HKDF 来源仍是原身份私钥，不能用设备根秘密替换它。

设备 PIN 只经实体按钮输入。浏览器不能提供 PIN、模拟确认或读取私钥。解锁材料仅在设备内短暂存在，锁定/断电/重启清理。USB、UART、日志、截图和崩溃报告不得暴露 Key、PIN、派生密钥或解封明文。

开发与发布固件隔离。开发固件可以使用独立测试 Key 和测试按键接口；发布固件彻底不包含模拟按键、绕过确认或原始 Key 调试入口。Secure Boot、Flash Encryption、调试/下载限制按具体芯片评估，烧熔丝有独立、明确操作步骤，不由普通编译或测试隐式执行。

## 3. 三按钮解锁

首版建议逐位数字轮盘，默认八位数字 PIN，长度、KDF 与失败等待参数待真机实测冻结。高级长数字/分组字符口令是后续可选项。不能把三按钮短按序列当成低成本强密码。

```text
          解锁钱包
        ● ● ○ ○ ○ ○ ○ ○
             ‹ 5 ›
         减少  输入  增加
           A    B     C
```

| 动作 | 解锁页面 |
| --- | --- |
| A/C 短按 | 数字减/加一，循环 |
| A/C 按住 | 有上限的连续调整 |
| B 短按 | 提交当前数字并立即隐藏 |
| B 长按 | 打开删除上一位/取消输入菜单 |

每位可随机初始选中数字；这只减少固定按键次数信息，不防拍屏。达到配置长度后解锁，失败清除输入。首次设置重复输入确认。修改 PIN 需重新认证，失败/断电不破坏旧封装。PIN 不改变业务 Key 或旧数据派生。

失败采用递增等待与跨重启保存计数，不能拔线恢复无限快速尝试。默认不设未经确认的自动擦除阈值；计数在 MCU 上的物理绕过风险明确，不能宣传成 Secure Element 等级。失败存储的磨损、断电原子性和篡改处理须设计。

## 4. 设备状态与 USB

区分未初始化、已初始化锁定、解锁但未建会话、已连接会话、待确认请求、迁移专用状态。锁定设备允许最小 info/配对流程，不允许业务签名。设备只允许一个活动控制连接，业务 App 会话在该连接内分隔。

认证加密连接采用用户在两端核对配对码的流程，防替换和重放；不能仅根据串口编号或设备名称配对。协议不绑定 USB class，转串口/原生 USB 只是适配层。锁定、通信失活、主机关闭会话和重启清空相关持续决定，重连新建运行世代。电池供电时也执行失活锁定，具体心跳/超时见协议冻结结果。

菜单、锁定和取消优先于主机新请求。设备只有一个活动业务请求，其余由 Keymaster 有界排队；新独立业务请求返回 busy，控制操作始终可达。握手后使用 REQUEST/RESPONSE/EVENT，不设置独立业务 ACK；最近结果缓存与单调接受水位共同防重放。具体规则见 USB 简化设计 §1。取消不承诺撤回已经交付的签名。

## 5. 业务白名单与持续决定

设备只支持能自己解析、重新构造签名对象的版本化操作。正式 Key 无任意 signDigest/signHash 接口。实验模式若后续提供通用接口，使用独立实验密钥，不能解锁正式 Key 的盲签权限。

目标范围：标准 BSV 的明确脚本支持集（首批 P2PKH）、费用池交易专用解析器、登记的身份/意图/Channel/文件声明签名、私钥导入导出与 PIN。Channel seal/open、现有 v3 本地秘密等兼容依赖按调用清单保留并显式列支持状态，不因收窄自动删除。费用池需按实际阶段/脚本/锁定/状态证据冻结，不等同于普通 P2PKH 或任意多签。每种协议有规范编码、对象/方向约束和独立授权。交易自算 sighash，核验前序输入金额/脚本证据、输出、找零、费用、网络及覆盖范围；不信任主机 change 标签或 fee 文本。复杂脚本/资产未知时拒绝，不能按普通 P2PKH 显示。

决定状态为未决定、会话允许、会话否决；本次允许/拒绝是当前请求的结果，不留下持续授权。持续决定绑定 Key、设备运行、连接、App 会话、操作版本、协议、对象、方向及具体限额。Channel 允许不包括付款、私钥导出、任意摘要或另一协议。

持续否决直接返回拒绝，不反复弹窗。设备的“会话授权”菜单可查看范围、状态、已执行次数并取消任一持续决定，取消后回到未决定。撤销推进授权修订号、取消未执行匹配请求，执行前再检查权限；主机不接收事件也无法绕过设备决定。超限不自动扩大，重新授权。

导出、设备擦除、修改保护设置不得持续授权。无可信时钟时，不仅凭主机给出的时间执行“未来 30 分钟”；优先连接会话、次数和预算限制，计时策略另行冻结。

## 6. 基础审核与三按钮 UX

设备解释支持的操作类型和基础事实，不解释公钥/交易概念、商业用途、企业身份、信用评分或申请条款。后者由 Keymaster 完成。设备无信用查询、服务信任根、Markdown 解析或服务正文加解密任务。

BSV 摘要从实际交易生成：收款、找零、金额、费用、网络和签名覆盖范围，完整地址/公钥可查看。费用池按冻结阶段显示池对象/双方、资金/本次与累计支付/余款、矿工费及适用锁定/退款条件；无法核验的条件不靠主机标签放行。

A/C 浏览摘要/范围/完整对象，B 打开决定菜单；本次允许/拒绝及适用的会话允许/否决明确。选择允许后独立长按确认，换页先松键、进度可见，返回/拒绝/锁定始终可达。持续决定可在设备取消，执行前再次核对范围与修订。

阅读期间冻结实际操作，变更重新审核；固定文案与字段来自设备模板/解析器，Keymaster 业务说明不得替换。仅保留必要字段滚动、位置恢复、多语言/缺字/控制字符及长度保护，不建设外部信用长文章节或强制阅读业务资料。

## 7. 多语言与预置开源字体

按语言/地区选择：en、zh-Hans、zh-Hant、zh-HK、ja，后续扩展 ko 等。每个固件默认编入一种目标语言、小型拉丁/数字字库及设备自有符号。不按“国家”推断字形；金额、公钥和协议字段不因本地化改变规范值。RTL/复杂文字需布局能力与独立验收，不只换字库。

预选：Noto Sans Mono 用于地址/公钥；Noto Sans CJK 对应地区字形用于正文；Fusion Pixel Font 作为精简像素备选。字体采用 OFL，须随源文件保留准确许可证、版权、版本、来源和哈希。只有文档候选，当前尚未下载或预置。

未来实现需提供本地字体资源和确定性构建预设，用户只选语言、字体和字集档位，不手工寻找字体或字符表。建议参数名 LANG、FONT_PROFILE、GLYPH_SET，实际构建命令待工具链确定。字集档位为 ui（固定文案）、common（固定文案和常用动态字符）、full（所选字体可用全字集，受分区预算约束）。

构建从所有目标语言文案、错误/恢复页和风险模板提取字形，再加入 ASCII、标点/数字和选定动态字集；重复字形去重，限制字号/字重。正文 20–24px、地址较小等宽字体是待真屏验证建议，不能为了省空间使重要汉字不可辨。

固定 UI 缺字/缺翻译使构建失败；动态缺字明确提示并可查看码点，不静默删除/替换后继续把名字当已核验。输出字形数、Flash 字节、RAM、最坏基础摘要布局内存和缺字报告，不能凭源 TTF 大小估计固件占用。变更语言固件保留密钥分区、兼容升级、清空会话，刷写方案不能默认整片擦除。

## 8. 迁移、导出与恢复

导入需设备主动进入专用状态，在确认配对后的认证加密通道接收原 Key，核对长度/曲线/公钥，再原子保存设备封装。返回公开迁移进度与持有权证明，不返回 Key。重试同一迁移可查询状态，冲突迁移拒绝。主机提交成功后才退出迁移流程；失败不静默变成另一个钱包。

迁回建议允许，但不复用原软件密码：设备菜单主动进入 → 重新 PIN → 固定警告私钥将进入软件环境 → 长按确认 → 一次性加密导出至 Keymaster 专用 Worker → 主机以新密码生成软件封装。是否保留设备副本、何时擦除先确认。删除设备不能先于主机可恢复提交；USB 与主机事务无跨设备原子性，按公开 journal 恢复。

必须有设备外恢复备份方案，格式准确恢复原单 Key，不假定导入 Key 对应 HD 助记词。恢复备份、设备保护封装和完整 Keymaster 数据备份分别说明。更换硬件保护口令不改变业务身份。设备擦除不承诺删除主机/用户备份。

## 11. 支付渠道与额度

插件和外部 App 均按可信调用方处理，不增加信誉或业务准入限制。所有使用金额的请求必须对应已注册渠道并携带渠道编号；插件仅受单笔免确认额度控制，连接 SDK 的 App 另受一次连接的累计免确认额度控制。超额要求实体确认，用户同意即可继续。

设备持久保存同一 Key/owner 绑定的渠道单笔配置及 App 默认会话累计额度；用户通过 Keymaster 设置并由设备确认必要授权。每次支付带渠道，设备自算金额，App 同会话各渠道累计。两项均未超额度（包含等于）时自动执行不弹同意页；超过任一项仍可经实体确认执行。

超额提供拒绝、仅本次；App 累计超限可提高当前会话额度并批准本次。计数不清零，不改未来默认或单笔额度。首次免确认/提高配置及会话预算设备认可；未同步/错身份不自动放行。计数及费用池核算按 VLP P0 冻结并以 PAY-01 至 07 验收。原持续决定不能绕过支付额度。

本节替代此前“所有私钥迁移显式不支持”的阶段状态，只收口已有同 Key 迁移需求；不新增信用查询或业务解释功能。

- [x] VLP 设备公开 journal：SDK TS/C++ 严格九字段、规范 CBOR、同绑定及线性阶段校验；真实记录持久化。Draft 0x22f / migration.status 只读公开状态，不授予密钥操作。
- [x] RocKey 主动导出与重新 PIN：本机菜单开启导出；A/C 选择数字、B 输入、长按 B 删除、长按 A 拒绝。复用 KeyStore 真实失败计数与等待；PIN 输入清零，成功后重新松键、读完摘要/风险、长按仅本次确认。持续许可和浏览器字段均不能代替。
- [x] Draft 0x230：migration.export 输出前持久化 device-committed；私钥经原加密 USB 仅传一次，query/replay 只保留完成状态。Worker 实际派生核对公钥，生成并解密回读验证新密码 KeyHold。源私钥、回读副本及异常路径缓冲清零。
- [x] Keymaster 硬迁软主流程：Worker 钱包迁移门禁排空已有 I/O，阻断新业务读写/签名；同一 IndexedDB 事务写目标 KeyHold、完整真实额度 bank 和 local-committed journal，保留身份世代、公钥、联系人、消息和其余业务记录。Window/插件只取得公开 DTO。
- [x] 独立硬件擦除：浏览器真实提交后发送公开 host-commit，不能由此自动擦除。设备再一次 PIN 与实体仅本次确认，先记录 erasing，再执行真实清理并清除 KeyStore/运行时两份 RAM 私钥，最后记录 erased。只有匹配浏览器提交的擦除回执才完成 journal；钱包锁定后用新密码解锁。
- [x] 旧 Key 仍在的恢复：专用连接重新验证同一原 Key，核对原 journal；prepared/device-committed 仍需本机重新开启导出、重新 PIN。local-committed 只继续原目标的确认/擦除，不重新封装或改写目标。恢复期间没有普通业务解锁。
- [x] 已无旧 Key 的回执恢复：Draft 0x231 使用 RAM 临时身份和实体配对，只核对浏览器已经原子提交的同一 journal/KeyHold/bank。临时公钥不写钱包记录、不冒充旧私钥持有权。设备只开放 status、recover-erased、complete；普通签名明确拒绝。erasing 的剩余清理需独立实体确认，存在任何 Key 文件时绝不走此入口；已持久化 erased 只核对回执。
- [x] 产品 UI：Key 管理页“迁回软件钱包”收集新密码；存储阻断页通过 Vault 私有恢复组件继续同一迁移，可明确选择“设备已擦除，仅恢复回执”。配对、PIN、导出与擦除决定保留在设备。设备保留公开回执；确认浏览器完成后，用户才能独立长按重置设备，USB 不自动创建新身份。
- [x] SDK 清理：关闭期间晚返回的一次性结果、无等待方/绑定不合法的 decoded 回复清零；通用 query 无再次获取私钥的路径。Consumer 固定 SDK 包及 manifest 同步真实文件 SHA-256，并明确登记未提交源覆盖，不伪装已发布版本。
