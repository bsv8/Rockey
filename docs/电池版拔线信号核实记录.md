## 只读诊断

使用 `m5stack-core-power-probe`，不实例化钱包 App/KeyStore、不读取钱包文件、不写 PMIC 配置、不提供测试签名或模拟拔线。屏幕/串口报告运行时间、ESP-IDF 实际复位原因、I2C 地址 0x75 的 0x70/0x71 原始状态。不存在可访问 PMIC 时报告 -1，不伪造状态。

诊断镜像只能归档在 `.pio/diagnostics`；发布扫描必须拒绝该镜像。刷写前备份启动/NVS/分区表与钱包 LittleFS，核对分区表，只写应用区。测试结束后恢复钱包固件，钱包持久数据保留。

1. USB 连接时记录基线：复位原因、运行时间、PMIC 原始状态。
2. 用户保持电池接好，拔 USB 后先观察屏幕，不立即插回：是否黑屏/重启，运行时间是否归零，`RESET` 一行是什么，PMIC 状态是否变化。
3. 用户提供拔线期间观察，然后插回 USB。重新插入/串口打开本身可能影响复位，不能用插回后的原因冒充拔线期间的原因。

`BROWNOUT` 可提示欠压复位；`PANIC`/看门狗可提示软件异常；`POWERON`/`UNKNOWN` 不能单独区分供电切换与所有外部复位路径。所有结论须与实际观察对应。如果供电切换使 MCU 先复位，软件不能把已经发生的复位追溯改为关机；需要继续核实稳定供电和可读物理信号。
