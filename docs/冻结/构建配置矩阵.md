# 冻结：构建配置矩阵

> 状态：与 `platformio.ini` 一致。用户只通过环境名选择语言、字体与字集档位。
> 参数语义见需求 §7；本矩阵是 `tools/build/main.sh` 映射的书面形式。

## 三条正交参数

| 参数 | 取值 | 来源 |
| --- | --- | --- |
| `LANG` | `en` / `zh-Hans` / `zh-Hant` / `zh-Hk` / `ja` | `platformio.ini` 的 `lang_*` 段 |
| `FONT_PROFILE` | `builtin` / `fusion-pixel` | `tools/fonts/sources/manifest.json` |
| `GLYPH_SET` | `ui` / `common` / `full` | `tools/fonts/main.py` |

编译期只能定义其中一个语言：`src/i18n/i18n.cpp` 在未定义 `ROCKEY_LANG_*`
或列号越界时报 `#error`，不会静默回落到某一种语言。

## 环境矩阵

| 环境 | LANG | FONT_PROFILE | GLYPH_SET | 档位 |
| --- | --- | --- | --- | --- |
| `m5stack-core-en` | en | builtin | ui | release |
| `m5stack-core-zh-hans` | zh-Hans | fusion-pixel | common | release |
| `m5stack-core-zh-hant` | zh-Hant | fusion-pixel | common | release |
| `m5stack-core-zh-hk` | zh-Hk | fusion-pixel | common | release |
| `m5stack-core-ja` | ja | fusion-pixel | common | release |
| `m5stack-core-migration` | zh-Hans | fusion-pixel | full | release |
| `m5stack-core-debug-zh-hans` | zh-Hans | fusion-pixel | common | release + LOG_LEVEL=3 |
| `m5stack-core-dev-zh-hans` | zh-Hans | fusion-pixel | common | dev |
| `m5stack-core-dev-en` | en | builtin | common | dev |

默认环境：`m5stack-core-zh-hans`。

## 字集档位

| 档位 | 内容 | 风险 |
| --- | --- | --- |
| `ui` | 只有固定 UI 文案的字形 + ASCII/标点/数字 | 动态文本（文件名、地址）可能缺字 |
| `common` | 固定文案 + 常用动态字符 | — |
| `full` | 所选字体可用的全部字形 | 受分区预算约束，可能超限使构建失败 |

固定 UI 文案缺字或缺翻译 → **构建失败**（`tools/fonts/main.py`）。
动态文本缺字 → 不静默替换成别的字，而是记录码点，
可在界面上查看（`display.cpp` 画占位方框，`app.cpp` 显示码点）。

## 已声明但当前不可用的预设

**`noto-cjk` 这个 profile 不存在**，配置里也已经不再声称使用它：
`platformio.ini` 的注释只列 `builtin | fusion-pixel`，本文第 1 节的矩阵同样如此。
`tools/fonts/sources/manifest.json` 只定义了 `fusion-pixel`（各地区比例字形 + 等宽拉丁），
`tools/fonts/sources/cache/` 里也只有 fusion-pixel 的 otf。
Noto Sans Mono / Noto Sans CJK 仍只是需求 §10 的候选，尚未下载、未固定版本与哈希。
R6 要求「没有下载/生成字体前不得标记本阶段完成」，所以 R6 仍未完成。

另外 `tools/fonts/main.py` 依赖 Pillow；本机环境缺 Pillow 时字体生成会失败，
因此**至今没有产出过一次完整的多语言构建**。

`platformio.ini` 还引用了 `ROCKEY_FONT_ASCII_BUILTIN`，但代码只检查
`ROCKEY_FONT_TABLE`（`src/ui/font.cpp:6`）—— 前者是死宏，已知不一致。

## 构建流程

```
tools/build/main.sh [环境...] [--all] [--upload <环境>] [--check-only]
```

第 0 步是主机侧门禁，不需要 ESP32 工具链，在任何机器上都能跑：

1. `tools/host-tests/main.sh`
   - `tools/syntax/main.sh`：对 `src/` 做 `-fsyntax-only`（用 `tests/host/stubs/`
     替身覆盖平台头文件）。明确不覆盖 `crypto/{digest,secp256k1,x25519,aead,rand}`，
     那几个依赖 ESP-IDF/mbedTLS 头文件。
   - `tests/host/test_proto.cpp`：编译真实的 `proto/cbor.cpp`、`proto/frame.cpp`、
     `store/crc32.cpp`，跑 CBOR 与帧层的正反向向量。
2. `tools/wire-encoding/main.py`：字段名长度守卫 + CBOR 键序 + `BeginMap` 计数。

之后才进入字库生成 → `check_i18n.py` → PlatformIO → 发布扫描。

## 换语言与升级

刷写不同语言固件**不得**整片擦除：`partitions/partitions_rockey.csv` 把
`/vault` 单独分区，密钥封装与迁移记录都在里面。换语言只换应用分区，
密钥分区保留；同时按需求 §7 撤销会话（语言变更属于重启，会清空持续决定）。

## 2026-10-10 产品 E2E 档位

`m5stack-core-e2e-en` 和 `m5stack-core-e2e-zh-hans` 编译真实产品 App，但只访问 `/e2e` 测试钱包目录。开发档位也强制目录隔离与测试外层复用帧；日志走独立 UART。正式档位继续直接使用 VLP，不包含注入接口。E2E 刷写使用 115200；先完整备份，空专用测试设备首次建盘需显式参数。详见[产品 E2E 施工单](../产品E2E需求与施工单.md)。
