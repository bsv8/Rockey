# RocKey 维护命令与工具目录

2026-10-11 用户要求：统一设备维护命令，列出钱包、刷指定 bin 且不刷新数据区、清空数据区；工具按 `tools/工具名/main.py` 或 `main.sh` 组织，原 scripts 合并；产品目录使用英文。

## 实现边界

统一入口 `./rockey`，实现位于 `tools/rockey/main.py`。`list` 列当前 CP2104 候选设备，不读取私钥；`flash` 检查固件、先备份且验证实际分区，只写 app0；`clear-data` 明确确认后先备份，只写有效空钱包 LittleFS。保留现有固件和浏览器状态，不提供整片擦除。多设备必须指定串口。

原 scripts 已迁至 tools，各工具独立目录。构建、PlatformIO 钩子、字体资源、门禁、文档引用同步迁移，不保留旧路径入口。字体和许可证放 `tools/fonts/sources/`。`tools/build/main.sh --upload` 调用统一 CLI。

`releases/YYYY-MM-DD/构建ID/环境/` 按 UTC 时间归档发布 bin，随附 SHA256 和字体清单；禁止同构建覆盖不同内容，二进制不提交 Git。开发/E2E 固件仍使用隔离测试流程，不放最终产品目录。

## 验证记录

- 真实 M5 CP2104 被 `list` 识别；`products` 和重复归档可用。
- 真实 Flash 备份分区通过布局验证；修改分区边界被拒绝。
- 未确认清空、不存在固件、被修改的实际固件 SHA256、不合格 E2E 归档均被拒绝，没有执行设备写入。
- Python 编译和 Shell 语法检查、迁移后真实产品主机门禁、中文构建、发布 ELF 扫描及自动归档通过。构建 ID `20261011T063754Z-2906911`。
- 本轮没有为验证新 CLI 再清空用户钱包；新 CLI 的 flash/clear-data 未额外执行实机写入。之前修正版刷写、空 LittleFS 清理的实机证据见渠道施工单。
