## 需求

- 默认无电池、USB 供电，不显示电池图标或电量信息。
- 本地 PIN 解锁后，空闲计时、浏览器关闭、串口通讯中断、USB 协议心跳超时均不触发钱包自动锁定。
- 通讯失活仍结束该次通讯会话、取消待处理请求、撤销会话授权，重新连接仍需新的加密握手和配对；不会沿用旧会话许可。
- 无电池时，物理拔掉 USB 即断电，内存解锁材料消失；重新接入电源后从锁定状态启动。
- 有电池时，只用真实物理 USB 存在信号触发拔线关机：擦除私钥解锁材料、取消待处理请求、清除会话授权，关闭屏幕并停止钱包运行。锁屏页也执行同样规则，重新插入并启动后进入 PIN 解锁流程。
- PIN 失败等待、显式本地锁定、改 PIN 和私钥迁移等既有操作规则仍生效。

## 实现

SDK 的连接重置仍擦除链路密钥和连接身份副本。RocKey `Runtime` 在该回调先撤销支付/通讯授权，再从当前已解锁的本地 KeyStore 重新准备连接身份，供新的握手使用；不重新解密持久私钥，不接受主机 PIN，不恢复旧授权。显式销毁/锁定设置 `closing_` 并擦除 KeyStore，避免回调重新准备身份。

移除了未使用的 `ROCKEY_LOCK_IDLE_MS` 配置及旧 `OnLinkIdle` 私钥锁定代码。物理 USB 检查在 `App::Loop` 的请求/按键处理前执行。

当前正式固件 `ROCKEY_HAS_BATTERY=0`，不采集电量、不轮询充电状态；菜单关机时尝试电源芯片的轻载关机配置，见 [菜单关机记录](./菜单关机需求与施工记录.md)。带电池的物理拔线检测档位使用：

```text
-DROCKEY_HAS_BATTERY=1
-DROCKEY_USB_PRESENT_GPIO=<已接入真实 USB 存在信号的 GPIO34/35/36>
-DROCKEY_USB_PRESENT_ACTIVE_LEVEL=1
```

低有效检测电路可选择 `ACTIVE_LEVEL=0`。信号由板级可靠 VBUS 检测电路提供，电平必须适用于 ESP32，并在拔线期间保持确定状态；不是把 USB 5V 直接接到 GPIO，也不是读取协议心跳或串口 DTR。启用电池但没有配置检测 GPIO 会拒绝编译。这是物理信号接入能力，不代表当前标准 M5 已有该检测电路。

M5Stack 官方文档表明部分 Basic 使用 IP5306_I2C，但充电/充满标志只用于推断外部供电，其官方说明也保留不确定性；不采用这些标志冒充可靠 USB 拔线检测。仓库以前将目标板写为“无 PMIC”的假设撤销，PMIC/PCB 修订及检测接线须以实际硬件核实：[M5Stack 电源能力说明](https://github.com/m5stack/M5Stack/blob/master/docs/Power_capabilities.md)、[官方寄存器手册](https://github.com/m5stack/M5-Schematic/blob/master/Core/IIC_IP5306_REG_V1.4.pdf)。
