## 0. 本轮修复摘要

上一版固件虽然存在，但请求路径**整体不可用**：握手发不出 `HELLO_ACK`、
加密会话从未建立、响应编码器被自己的确定性编码器拒绝、交易请求必被判为
malformed，且整棵树**从未通过编译**。本轮修复并加了上面四道门禁防止复发。

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 方向密钥写反，`c2s`/`s2c` 共用同一把密钥 | 方向分离失效 | `link.cpp` 分别派生、解密用 `c2s` |
| `HELLO_ACK` 键序违规 + 输出缓冲重叠 `memcpy` | 握手**必失败** | 重排键序、编码到独立缓冲 |
| 加密会话从未开启（`OpenSession` 无调用者） | 所有业务请求被静默丢弃 | 新增 `PROVE_POSSESSION`/`PROVE_OK`，持有权证明通过后开会话 |
| 5 处响应编码器键序违规 | 签名/封装结果发不出去 | 键序全部重排 |
| `Reader::EndArray()` 计数错误 | **`tx.p2pkh-sign` 必被拒** | map/array 计数分离 |
| 13 处字段名长度守卫写错（含 `rawTx`） | 多个字段永远匹配不上 | 全部改正，并加静态检查 |
| AEAD 的 AAD 缓冲 8 字节却写 10 字节 | 栈溢出 + AAD 含栈垃圾 | `kAadLen = 10` |
| `FrameReader` 不报告消费量，重投同一批字节 | 帧重复投递 | `Feed()` 返回 `consumed`，`Link::Poll` 按量前移 |
| `SkipItem` 递归无深度限制 | 主机可致栈耗尽 | 深度限制 |
| `TxSignContext::pub33` 从未赋值 | 交易路径空指针解引用 | `Prepare()` 填入设备公钥 |
| sighash 输出缓冲按 9 字节脚本定尺 | 真实 P2PKH 输出即栈溢出 | 按 `kMaxScriptLen` 定尺并加边界检查 |
| PIN 失败等待落盘 `millis()` 时间戳 | **每次重启把等待抹掉** | 改为落盘等待时长，计数跨重启递增 |
| `Reader::Rebuild()` 哨兵越界写 | 满屏长文越界 | 哨兵预留一格 |
| 日志与协议共用一条串口 | 日志行破坏帧流 | 发布档位日志改走 UART2 |
| `Rect{...}` 窄化错误（数百处） | **整棵树编译不过** | `Rect` 增加收窄构造函数 |

## 0b. 第二轮修复摘要（密码学与授权边界）

第一轮修的是"编译不过 / 请求路径不可用"。第二轮是在主机上把真实实现拿成熟
实现对照之后发现的，其中前两条属于**功能从未可用**：

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| `aead.cpp` 解密方向把 GHASH 算在明文上 | **解封、解本地秘密、解任何加密帧全部失败** → 设备根本解不了锁、协议一条也通不了 | 按方向取密文进 GHASH |
| RIPEMD-160 右线移位表误填成 RIPEMD-128 | **所有 HASH160 与 P2PKH 地址都是错的**，且无任何报错 | 改用 ESP-IDF 自带 mbedTLS RIPEMD-160 |
| `aead::SelfTest()` 拿 AES-256 输出比 AES-128 官方用例 | 每次上电误报失败，正好盖住上面两条 | 改为与 mbedTLS 对齐的 AES-256 向量 |
| `check_test_vectors.py` 只 grep 源码里的期望常量，从不执行实现 | 上面两条都因此显示"通过" | 改为编译并执行固件代码后比对 |
| `identity.prove/authorize` 直签主机给的 32 字节 | 可用交易 sighash 当 challenge 换走交易签名 | 改为域隔离的设备自建摘要 |
| `ProvePossession` 直签主机 challenge | 同上，且可从链路层直接换 | 改为域隔离摘要并绑定 deviceRunId/连接/会话 |
| `secret.open` 要求 4 个字段，`seal` 产出 5 个 | 设备自己的密文永远解不开，旧 v3 数据也就打不开 | 字段数改为 5，并加往返测试 |
| `Policy::Find` 只扫到 `s_count_`，槽位删除后不压缩 | 靠后的授权对查找不可见；`Evaluate` 对 `kUndecided` 直接返回 `kAllowed` | 扫全部槽位并跳过未激活项；未决定一律回到需要用户 |
| `CancelSession` 按 `createdMs` 反查 | 同一毫秒创建的两条会互相误删 | 按槽位下标删并压缩数组 |
| 限额从不生效（`budgetSats < 1` 恒假、`usedCount` 不增） | 次数/金额上限形同虚设 | `Evaluate` 接受本次金额，`Consume` 累加次数与金额 |
| `MatchKey` 不填 protocol/direction；对象摘要取消息前 16 字节 | 一次授权外溢到其它协议、对端与消息 | 全部改用域隔离的对象摘要 |
| `ChannelSealKey` 每次随机派生临时密钥且不回传 | seal/open 无法闭环 | 改为确定性 X25519 静态-静态 ECDH（**未与 Keymaster 对齐**） |
| `P2pkhAddress` 向 25 字节缓冲写 32 字节摘要 | 栈溢出 28 字节 | 校验和单独缓冲，只取前 4 字节 |
| sighash 预映像缺 `nSequence`，`sequence` 只保留最高字节 | `0xFFFFFFFF` 被当成 `0xFF`，**签名摘要算错** | 保存与序列化完整 4 字节，并补齐预映像字段 |
| `P2pkhAddress` 未校验被签输入归属 | 主机可把别人的 UTXO 指成 `inputIndex` | 增加 hash160 归属校验 |
| 交易审核只显示总额/费用/找零，不显示收款方 | 用户看不到钱付给谁 | 逐项列出收款地址与金额（由设备从输出脚本解出） |
| `proven` 由主机声明且会影响风险提示 | 浏览器可自称"已验证" | `proven` 只决定是否追加"未验证"，固定显示"由主机提供、本机未验证" |
| 确认页/拒绝确认页无 A/C 处理，`summaryScroll_` 恒为 0 | 用户进入确认页后**无法拒绝**，且第 6 行起的摘要与第 3 条起的风险看不到 | 补齐按钮处理与滚动，确认页可返回 |
| `FinishRequest` 不切页 | 队列停在授权页，下一个请求永远不处理 | 统一收尾并回到中性页 |
| `PumpQueue` 的配对条件写反 | 配对成功后所有请求都不处理 | 改为"已配对且会话有效" |
| 已完成 requestId 可重放；断线不清 `active` | 同一 requestId 可二次签名 | 增加会话内结果缓存；`ClearQueues()` 统一清理 |

## 0c. 第三轮修复摘要（HKDF / X25519 / 交互与授权边界）

第二轮的"1145 条断言全绿"同样不可信：断言只是把实现和自己比。
这一轮把密码学实现**和成熟实现逐字节对照**，立刻暴露了三条从未可用的事实：

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| `HkdfSha256` 的 expand 从未用 PRK 初始化 HMAC | **封装密钥、本地秘密派生密钥、链路 c2s/s2c 密钥全部退化成公开常量**；任意同位数 PIN 都能解封；本地秘密互相可解 | 改用 mbedTLS HKDF |
| X25519 模数写成 2^255-1、u 坐标按大端读、ladder 初值写反 | 握手两端算不出同一共享秘密，`SelfTest()` 一直失败 | 按 RFC 7748 重写（含小端转换与正确初值） |
| X25519 在 `inv_mod` 失败时输出未求逆的 `x2` | 低阶点得到**非零且错误**的"共享秘密"，全零检查拦不住 → 小子群攻击 | 无穷远点输出全零并拒绝 |
| `SelfTest()` 里 X25519 的"RFC 向量"常量并非 RFC 向量 | 自检永远失败，把真问题盖成环境问题 | 换成 RFC 7748 Alice/Bob 与迭代向量 |
| `aead::SelfTest()` 拿 AES-256 输出比 AES-128 用例 | 每次上电误报失败 | 第二轮已修为与 mbedTLS 对齐的 AES-256 向量 |
| `App::Begin()` 忽略 `SelfTest()` 返回值 | 自检全错也照常配对与签名 | 自检失败则拒绝一切业务请求 |
| Channel 授权对象对 seal 也取 `ciphertext` | **每个合法 seal 请求被判 malformed** | seal 绑明文、open 绑密文，并交叉校验对端公钥 |
| 结果缓存满后覆盖最老槽位 | 超过 8 条后旧 `requestId` 可**再次执行** | 缓存满则拒绝新请求（不遗忘旧 ID） |
| `HoldConfirm` 不看松键栅栏 | 换页时仍按住的 B 会自己走完进度 → 没松开就确认 | 栅栏期间清空并禁用计时 |
| 擦除页按住计时用函数内 `static` | 离开页面/换页后计时不清零 | 改为成员变量，离开页面即清零 |
| 金额用 `%lu` + `unsigned long` | ESP32 是 32 位，超 `UINT32_MAX` 的聪数**显示错误**（签署值仍正确） | 统一 `%llu`，并加格式化回归断言 |
| 必需章节/重大警告只是文案标注 | 可以不经过就签署 | 增加必需内容门禁，未逐项看过进不了确认页 |
| 确认页按钮标签与实际动作不符 | 标签写"返回/查看范围"，实现里是滚动/返回 | 标签与动作对齐 |
| `requestCommitment` 缺失按全零处理，且从不校验 | "承诺覆盖实际对象"形同虚设 | 缺失/全零即拒；承诺并入匹配键，持续授权只覆盖被承诺过的请求 |
| `CancelAll` 的长按分支被外层条件挡住 | "长按全部撤销"永远触发不了 | 长按先判 |
| 按键重复发出一次后不再武装 | 按住无法持续滚动 | 每次发重复后重新武装 |
| `check_release_build.py` 缺 `nm` 时跳过符号扫描 | 发布扫描在没查的情况下报"通过" | 缺工具/无符号一律失败（exit 2） |

## 1. 施工顺序与归属

Rockey 负责板级支持、固件密钥保护、解析/密码学、设备策略、三按钮 UI、多语言字体、USB 设备侧和固件测试。Keymaster 负责统一 Vault、浏览器 USB 桥、数据库生命周期、业务构造和主机 UI。共同协议在本仓库唯一维护，双方固定版本及向量。

建议未来模块按 board、transport、protocol、key-store、crypto、operations、policy、ui、i18n/font、migration 和 tests 分开；目录命名在工具链选定后确定，不为目录骨架假称功能完成。任何实现并行工作先明确文件归属，不能回退他人变更。
