> [设备需求](./需求.md) · [设备施工单](./施工单.md) · [Keymaster 需求](../../keymaster.cc/docs/proposals/rockey/Vault软硬件统一需求.md)。

## 1. 协议目标与权威

USB 只搬运字节，不证明 App origin、设备身份或操作安全。主机向设备提供完整可核验操作和辅助证明，设备自行解析、生成安全摘要、匹配授权并执行。主机不能提交一个 digest 和一段说明让设备假称理解。私钥正常业务不离开设备；主动迁回是专用的一次性例外。

Keymaster Coordinator 是浏览器会话/存储权威；Rockey 是设备密钥和物理授权权威。请求需同时符合两端的权限。显示名称、域名及主机声称 verified 均不等于设备验证；App proof 能证明签发关系，不自动证明运行环境或 origin。可信度机构签名证明来源和内容，不保证交易安全。

## 2. 字段概念（尚非 wire 编码）

| 概念名 | 中文含义与要求 |
| --- | --- |
| protocolVersion | 协议版本，未知版本拒绝，不隐式降级 |
| capabilities | 操作/解析器及版本，区分基础、实验与迁移能力 |
| publicKeyHex | 当前业务身份公钥，压缩形式；wire 可改用定长字节 |
| deviceRunId | 本次设备启动的随机世代，重启不同 |
| connectionId | 已配对认证连接标识，重连不同 |
| walletGeneration | 主机当前钱包身份世代，注销重建不同 |
| backendGeneration | 主机当前后端绑定世代，同 Key 迁移也变化 |
| hostRunGeneration | Coordinator 运行世代，重启不同 |
| sessionId / sessionEpoch | 操作所属 App/Keymaster 会话及代际，不跨会话授权 |
| requestId | 连接/会话内唯一请求关联标识，重放检测 |
| operation / operationVersion | 已支持业务操作及其精确编码版本 |
| requestCommitment | 对规范实际操作及安全相关辅助内容的密码学承诺 |
| decisionRevision | 设备授权修订号，撤销后旧队列/请求不可执行 |
| migrationId | 专用迁移标识，仅用于公开恢复进度，不含秘密 |

nonce（随机挑战）、消息序号、长度/分片等传输字段与业务 requestId 分别校验。请求承诺必须覆盖实际签名/解密对象、网络、关键范围、接收公钥、证据和显示相关内容；具体覆盖规则逐操作固定，不能任由主机选择字段。主机世代是绑定材料，不能当成设备认证事实。

## 3. 通道、安全与传输

握手流程：查询最小 info → 版本/能力选择 → 双方临时密钥及挑战 → 两端显示同一短配对码，设备实体确认 → 建立认证加密通道 → 已解锁设备证明持有业务 Key → 建立会话。配对码、握手 transcript（握手记录）、角色和版本必须绑定，防中间人/降级。设备运行、连接和会话重建不得复用旧消息密钥/nonce。

具体密钥协商、签名、AEAD、KDF、握手认证和序号算法在 Gate 0 选用成熟方案冻结；当前不自行创造未审查的密码学协议。Key 导入/导出必须等到实体配对完成后发生。已配对通道仍不能替代设备上的操作确认，也不能防被恶意主机在导出获准后读取 Key。

wire 必须定义帧边界、长度、类型、分片 ID/序号、最大消息、分片和队列额度、超时及认证失败恢复。USB 串口有断包/粘包，不以一次 read 等同于一帧。不分配主机自报的无界长度，不支持外部压缩炸弹。取消与控制消息有独立优先级，但不能跳过认证。

首版 BASIC/FIRE 候选走 Web Serial；原生 USB 后端后续可用同一上层协议。主机允许一个控制桥，设备允许一个控制连接。串口失活通过可验证连接存活及超时处理，具体间隔与检测条件冻结；不能凭 USB 供电持续就保留 grant。

## 4. 操作目录与安全分类

| 类别 | 初始语义操作 | 设备责任 |
| --- | --- | --- |
| SYSTEM | info、lock、连接存活、会话关闭 | 最小暴露，锁定幂等，状态可观测 |
| IDENTITY | 当前身份证明、地址核对、身份/意图授权 | challenge/用途/对象/会话绑定 |
| TRANSACTION | BSV P2PKH 签署 | 重建交易及 sighash；核验前序证据、找零/费用/覆盖范围 |
| CHANNEL | 公共消息、Hash 请求、私密消息签名与 seal/open | 固定编码/协议、方向和对象约束 |
| LOCAL_SECRET | v3 seal/open | 内部派生，scope 固定绑定，不暴露长期派生密钥 |
| CONTENT | 文件摘要声明签名 | 显示主机计算摘要及用途，避免交易语义混淆 |
| EVIDENCE | 临时接收公钥、导入签名/加密可信度证明 | 校验信任根、签名、nonce/对象/请求绑定 |
| MIGRATION | 主动导入、持有权/兼容证明、进度查询、主动一次性导出 | 专用设备状态与物理确认，不持续授权 |

目录是语义范围，不是已定命令名。交易/意图/消息解析器不接受任意算法/路径/网络扩展。FIDO 不作为上述操作的等价替代；普通 WebAuthn 不被当成钱包签名。正式 Key 不暴露通用 SIGN_HASH、AES、ECDH 或 HKDF 接口供任意组合绕过语义。

BSV 操作必须冻结 raw tx、前序交易/输出证据、输入索引、金额、脚本、网络与 sighash 的对应关系。设备验证主机提供的前序字节及 txid/outpoint 绑定，但不把这等同于已验证链上确认/未花费状态；链上事实缺乏证明时如实标注。找零必须符合设备从当前 Key 派生的受支持规则。未知脚本、异常覆盖范围和无法解释的资产拒绝。BTC PSBT 不自动成为 BSV 的格式契约。

## 5. 旧数据密码学兼容

身份使用原 32 字节 secp256k1 私钥和压缩公钥。签名显式区分 strict DER 与 64 字节 r||s compact，哈希/low-S 等规则以现有软件实作和冻结向量为准。不得隐式二次 hash。不把 compact 当作带恢复 ID 的其它格式。

本地秘密当前 v3 `keySource=active-key-hkdf-v1`。现有派生输入为私钥、HKDF-SHA256、salt 文本 `keymaster.vault.local-secret.v3`、info 为小写公钥文本 + NUL + scope，输出 256 bit。业务 AAD 基础文本 `keymaster:local-secret:v3|` + scope；现有 crypto 对 envelope salt 的额外 AAD 绑定和 AES-GCM 字节格式须按源码/向量完整冻结，不能只复制这段摘要就实现。

Channel 协议编码、签名/Hash、私密 seal/open、nonce 与 key agreement 以当前协议 SDK 的确定向量固定，不能手工改写后宣称兼容。消息正文可按协议类型细化解析器；没有解析器的 body 不自动享有会话授权。

兼容测试使用公开测试 Key、已固定输入/随机源及旧软件生成样本。真实部署随机签名/密文通常只要求语义、验签、双向解封兼容，不要求随机字节一致。设备内部保护密钥、PIN 和备份算法不改变业务派生结果。

## 6. 授权状态、事件与结果

匹配键由业务 Key、设备运行/连接、主机运行/钱包/后端世代、App 会话、操作版本和范围组成。允许与否决是不同决定，持续否决匹配优先于执行；范围重叠的确定优先级在 Gate 0 冻结。未知类型/缺字段拒绝，主机不能带 approved=true。

设备决定：未决定 → 本次执行/拒绝，或记录会话允许/否决。用户取消任何持续决定 → 未决定并推进 decisionRevision。App 会话关闭、锁定、断线/失活、迁移、重启清空相关决定。持续决定不落盘恢复，PIN 失败计数与持久迁移状态可落盘。

状态至少区分：received（已收）、queued（排队）、awaiting-user（等待用户）、executing（执行）、completed（完成）、denied（拒绝）、cancelled（取消）、expired（失效）、unknown（主机无法确定执行结果）。传输 ACK 不等于授权或签名成功。重复 requestId 不能再执行；短期缓存已完成结果及其承诺/会话，缓存与查询限额冻结。

设备事件包含请求状态、授权变更、锁定和会话结束；事件有序号/修订，主机忽略旧事件。执行结果绑定请求承诺、公钥及会话代际。设备自行拒绝撤权后执行，主机交付前再复核。取消只有尚未执行时能保证未执行；执行中/已签时明确实际状态，不承诺撤回签名。

错误类别至少包括 locked、busy、unsupported、version-mismatch、wrong-key、invalid-request、invalid-evidence、denied-once、denied-session、revoked、disconnected、timeout、result-unknown、migration-conflict；最终 wire 错误码在 Gate 0 冻结。错误无秘密，未知结果不自动重试。

## 7. 阅读内容与证据绑定

安全模板和按钮来自固件，外部包仅提供结构化事实、说明和证明。正文绑定实际 subject 公钥、操作承诺、机构/签名、查询 nonce、有效期/时间来源；加密包绑定设备临时接收公钥和对应请求。只有解析/签名/对象/承诺都通过才显示“证明已验证”。时间无法验证则单独显示，不凭主机时间消除警告。

规定 UTF-8、规范序列化、重复键处理、允许字符/控制字符策略、章节和总字节上限。超限不能截掉重大风险再批准。缺字不伪装成完整名称。阅读开始后内容冻结；可选说明变更也不无提示覆盖，安全相关变更必须重新确认。用户无需滚过全部长文，必须经过设备生成的操作摘要和重大警告。

## 8. 迁移事务

软迁硬公开阶段：host-prepared（主机冻结）→ device-staged（导入准备）→ device-committed（设备封装持久完成）→ host-committed（主机绑定提交）→ cleaned（旧软件活动材料移除）。各状态有 migrationId、公钥、方向和格式版本，不含秘密。设备提交与主机提交不宣称跨设备原子。

重启可查询匹配迁移进度并核验持有权。主机提交前保留软件可恢复记录，主机提交后无自动软件回退。未完成迁移保持受限模式，不并行批准两个后端业务。PIN/封装中断不破坏已提交旧封装。硬迁软方向先主机验证新封装、提交，再处理设备副本；是否擦除是尚待确认的产品策略。

设备编号不能用于恢复 Key；保留相同公钥和密码学持有权才能连接旧数据。注销浏览器不是 MIGRATION 的同义命令，不自动擦除设备。

## 9. Gate 0 冻结清单与交付

实施前双方完成：具体板型/USB；规范编码（如确定性 CBOR 或其它成熟格式）、整数/金额/字节表达；完整操作 schema；握手/认证/AEAD/KDF；Key 封装和恢复备份；队列/字节/章节/分片/超时上限；支持脚本/sighash/Channel 类型；错误/事件/查询/重放规则；时间与机构信任根；迁移记录和设备副本策略。

建议将冻结规格置于本目录的版本化协议子目录，公开黄金向量置于 Rockey `test-vectors/`，包含 manifest、规范字节、公钥、摘要/结果、软件版本和哈希。Keymaster 测试消费固定版本/哈希，不运行时任意拉取。具体路径在 G0 固定；本轮未创建代码或 fixture。

必备负向向量：换公钥/收款输出/网络/找零/费用、摘要与显示不一致、跨会话授权、撤权后排队执行、重放/乱序/超长、错误机构签名/请求绑定、缺字/控制字符、迁移冲突。仅正向验签不能证明授权安全。
